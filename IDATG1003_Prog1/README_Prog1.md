## Final Project for IDATG1003
The final project upon which our grade was judged in IDATG1003 was months-long project in which each student had to work on their own to develop an application according to the specifications and criteria given by the course. This project was given in three parts - each weeks apart, with the goal of being done with each part before the next so there would be ample time to modify and improve the final program before submission. The program was to become an application serving as an Activity Log, letting it's user log, save and read logs of various activities they participated in, where the later stages of the project included the ability to have groups of users with unequal access to the log entries, and the ability to share entries between users.

My work on this project was off to a strong, if mistaken start. Through an error, our Assignment Text included specifications for later parts of the project during the first stage. This, combined with me getting eager and skim-reading the earlier specifications, resulted in me jumping straight into the deep end rather than taking the step-by-step approach that was recommended. In practice, this meant that I began the project with a plan made up myself for how I wished to structure the final program, with classes made for a User Interface and file-sorting only to later realise that the project was laying out specifically what to do in the first stage.

Despite this setback forcing me to redo some work to better fit the project criteria, I nonetheless got to work with enthusiasm on the solutions I had in mind. The totality of the project was both a great experience for me to learn from as well as an opportunity to truly have fun with the work, diving into how to properly code in Java. Each new feature, paramater or UI element forced me to adapt my vision, to research syntax and existing function libraries and develop my understanding of Java as a language to the point that, when nearing the end of the project, I felt truly skilled in the principles behind the work. I developed from stumbling through basic method-construction into being able to effectively build new ones on the fly, troubleshooting my code without major issues and understanding how best to adapt when new functions were needed.

Although certain parts of the project, such as the ability to seperate users into different groups and thereby limit their access, introduced challenges that forced me to reconsider the work I had already done along with doing large-scale editing and troubleshooting, each new challenge was met with enthusiasm rather than frustration. I enjoyed not just the work itself but all that I learned from it, to the point that it felt more like I was having fun and playing around near the end rather than simply working to finish the task. I felt enjoyment and a drive to work harder the further things got, determined not just to get a good grade but to increase my understanding and skill.
